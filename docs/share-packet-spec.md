# 最小共有パケット仕様 v1

## 目的

被害者が証拠原本や自由記述を渡す前に、支援主体が事件の規模、対象可能性、証拠保有状況を把握できる最小データ形式を定義する。

これは正式な相談受付、委任、授権、訴訟参加、損害賠償請求ではない。支援主体が案件を扱うことも保証しない。

## 生成と移動

1. 利用者が端末内で対象可能性と証拠保有状況を整理する
2. 「支援団体への情報提供を検討したい」を選ぶ
3. 共有パケットに含む項目と除外項目を確認する
4. 利用者の操作でJSONファイルを端末に保存する
5. 利用者が自分で選んだ支援主体へ、自分の判断でファイルを渡す
6. 支援主体はレビュー画面でファイルを端末内集計する

試作段階ではRightsRelayサーバーを経由させず、連絡先も収集しない。

## 許可する項目

| 項目 | 内容 | 必要性 |
|---|---|---|
| `schema` | 形式の識別子 | 誤った形式の混入防止 |
| `packetId` | パケットごとのランダムUUID | 同一ファイルの重複除外 |
| `incidentId` | 公開事案ID | 事件の混同防止 |
| `ruleVersion` | 判定規則の版 | 集計条件の再現 |
| `assessment` | 可能性あり／不明／可能性低い | 初期トリアージ |
| `answers.membership` | 会員関係の区分 | 公表対象条件の確認 |
| `answers.notice` | 個別通知の受領区分 | 公表対象条件の確認 |
| `evidenceHeld` | 保有証拠の種類だけ | 原本受領前の準備状況 |
| `intent` | 更新・支援レビュー・調査への意向 | 用途別の意思確認 |
| `consent` | 目的・受取主体の選択・法的関係なし | 誤解防止 |

## 禁止する項目

- 氏名、住所、電話番号、メールアドレス
- 会員番号、契約番号、車両番号
- 通知メールの本文・画像・ヘッダー
- 免許証、パスポート、マイナンバー、カード情報
- 証拠原本、領収書、被害明細
- 自由記述の端末内メモ
- IPアドレス、端末識別子、広告ID
- 正確な作成時刻、位置情報

未知の項目が一つでもあるパケットは受け入れない。禁止項目らしき値を削って受け入れるのではなく、ファイル全体を拒否する。

## 同意境界

パケットの書き出しは、外部送信でも正式同意でもない。利用者が具体的な支援主体へ渡す直前に、別途以下を示す必要がある。

- 提供先の正式名称
- 提供する項目
- 提供目的
- 保持期間と削除方針
- 問い合わせ先
- 撤回できる範囲
- 正式受付・委任・授権との関係

v1の `recipient: user-selected-support-body` は、利用者が受取主体を後から選ぶことを示すだけで、提供同意を表さない。

## 受入検証

- 一度に100ファイルまで
- 1ファイル64KBまで
- JSONオブジェクトのみ
- 許可リストにないキーを拒否
- 列挙値と型を厳密に確認
- 事案IDと規則版の一致を確認
- UUID形式を確認
- 同じ `packetId` は集計時に重複除外
- ファイル名を画面・集計・ログに残さない
- 読み込んだデータをブラウザ保存しない

## 集計出力

支援主体向け集計からは `packetId` を除き、次の件数だけを書き出す。

- 有効パケット数と重複数
- 対象可能性別件数
- 会員関係別件数
- 個別通知の受領区分別件数
- 証拠種類別件数
- 用途別意向件数

少人数セルの再識別対策は、本実証で支援主体へ外部共有する前に決める。公開集計では原則として5件未満を丸めるか非表示にする。

## v1で証明しないこと

- 1人1票であること
- パケット作成者が実際の被害者であること
- 回答や証拠が真正であること
- 個人に連絡できること
- 法的請求が成立すること

これらが必要になるのは正式受付以降であり、個人を直接特定する情報を除いた規模把握とは別のデータ領域・権限で設計する。

## 事件横断化

このv1はタイムズカー事案専用であり、`answers.membership` と `answers.notice` を別事件へそのまま流用しない。複数事案に対応するv2案と移行条件は[事件横断データモデルの一次検証](cross-incident-model.md)に定める。
