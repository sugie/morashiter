msnc 環境構築案

設計PRの次の工程として実施する案です。この文書を保存した段階では、依存ライブラリのインストール、コンテナ起動、DB作成、実サイトへのアクセスは行っていません。

1. 開発構成

Mac
  Docker Compose（msnc開発用の独立プロジェクト）
    api        Laravel / 管理・保存処理
    msnc       同じイメージ / Laravelキューワーカー
                 └─ Pythonコマンド / BeautifulSoup抽出
    scheduler  同じイメージ / 定期実行
    postgres   mrst開発DB / 専用ボリューム
  非公開資料：開発中は専用ローカルディレクトリ
  AI接続：mock
  ニュース取得：初期はfixtureのみ

Pythonはmsncと同じコンテナに配置し、ネットワークサービスにしません。Laravelから標準入力でHTMLを渡し、JSONを受け取ります。単独Pythonコマンドでもfixtureを検証できる構造にします。

2. ランタイム・依存関係

項目構築案
PHP / Laravel既存services/api/composer.lockの構成を基準にcomposer install。PHP要件は既存composer.jsonに従う。DB操作を伴うcomposer setupを無条件に実行しない。
Pythonコンテナ内に専用venvを作成。Pythonのバージョンはベースイメージで利用できる対応版を検証して固定する。MacのグローバルPythonへ直接pip installしない。
抽出beautifulsoup4とlxmlを候補とし、対応確認後にバージョンとハッシュを固定。パーサーを明示。JSON・HTMLの媒体別fixtureで出力の安定性を確認する。
試験Pythonはpytest、Laravelは既存PHPUnit。競合試験はPostgreSQLで行う。インストールとバージョン選定は実装時に公式情報・既存イメージとの互換性を確認する。
運用ツールDocker Compose、Git、Composer。PythonのHTTP取得ライブラリは初期抽出プロセスに導入しない。HTTP取得はLaravelの安全な取得サービスに集約する。

3. 作成・変更予定ファイル

compose.msnc.yaml                     独立した開発サービス・ボリューム

既存LaravelディレクトリにはAGENTS.mdのセットアップ規約があります。実装開始時に規約とPHP/Composerを確認し、必要なLaravel Boostの導入を先に行います。既存の未追跡Laravelソースは今回の設計PRには含まれないため、実装ブランチで依存する基盤ファイルを確認し、秘密情報・取得資料を除いて記録します。

4. 設定と隔離

  • Composeプロジェクト名をmrst-msnc-devとし、既存rightsrelayのDB・ボリュームを再利用しない。DB名はmrst、ユーザー・パスワードは専用設定。
  • 秘密情報はgit対象外の環境ファイルに保存。配布する.env.exampleにはキーや実パスワードを入れない。
  • Pythonコマンドのパスと媒体コードは固定の許可リスト。入力2MiB、出力1MiB、抽出15秒。外部通信・DB接続をPythonの責務に含めない。
  • QUEUE_CONNECTION=database。msncキューだけを処理する専用worker。worker timeout=120秒、retry_after=180秒を初期設定案とする。
  • schedulerは1プロセス。多重実行の防止は共有DBの一意制約とロックを用いる。
  • 開発資料はstorage/app/private/msncに保管。本番は公開バケットとは別の非公開ストレージへ切り替える。
  • 初期は外部取得を停止し、AI_PROVIDER=mock。実媒体の有効化とAI課金接続を別々に制御する。

5. 構築順序

  1. 設計PRを作成・確認後、実装ブランチfeature/msnc-crawlerを作成。実装基盤の追跡対象を整理。
  2. 既存Dockerfile・依存ロックを確認し、Pythonを含むworkerイメージをビルド。
  3. 専用PostgreSQLを起動し、空のmrst開発DBへ必要なマイグレーションを適用。
  4. Python抽出コマンドをfixtureで検証し、Laravelからの標準入出力連携を確認。
  5. DB保存・再試行・ストレージ障害・ワーカー停止をfixtureで試験。
  6. workerとschedulerを起動し、期限到来から取得待ち・抽出・判定要求まで連携。
  7. Security NEXT、ScanNetSecurity、ITmedia NEWSの取得条件・対象URLを確認し、媒体ごとに低頻度で疎通確認。

6. 構築完了の条件

  • 別の開発環境でも固定依存から同じイメージを構築できる。
  • 外部通信なしで3媒体相当のfixtureから期待するJSONを抽出できる。
  • Python異常終了・タイムアウト・不正JSONをLaravel側が検知し、取得成功と記録しない。
  • 同一処理の再実行で資料や判定要求が増殖しない。
  • 既存DB・公開オブジェクトストレージ・プロトタイプ配信に影響しない。
  • 停止・再開・試験・失敗確認のコマンドが文書化されている。

msnc実装計画の取得安全性・永続的な再投入・受入試験に従います。
