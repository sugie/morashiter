# 被害経験者向けユーザビリティテスト手順 v1

## 目的

RightsRelayが、個人情報を追加収集せずに次の三点を実現できるかを検証する。

1. 利用者が自分の対象可能性を誤解なく確認できる
2. 証拠原本をアップロードせず、手元で残すべきものを理解できる
3. 端末内の意思記録と、支援主体への正式な外部提供を区別できる

製品への好意ではなく、タスク成功、誤解、離脱、不安を観察する。

## 対象とサンプル

- 第1ラウンド: 漏えい通知を受けた経験のある人 5人
- 第2ラウンド: 第1ラウンドの修正後に別の5人
- Gate B: UIを固定し、さらに別の10人
- 実害あり／なし、現会員／退会者が片寄らないようにする
- 1回30分。原則として録音しない

実際の通知メール、会員番号、免許証画像、氏名、連絡先は見せてもらわず、記録もしない。

3段階で合計20人とする。UIを変更したラウンドの数値を、同一バージョンの20人として合算しない。

## 事前準備

- 新しいプライベートブラウズ画面で試作を開く
- 参加者には架空の状況で操作してもらう
- 「法律相談ではない」「答えに正解はない」「画面を評価する調査」と伝える
- 観察者は `V-001` のような匿名IDだけを用いる
- 参加者が研究欄の「検証を開始する」を自分で押すまで計時しない

## シナリオ

> あなたは以前タイムズカーを利用しており、今回の漏えいに関するメールを受け取りました。実際の個人情報は入力せず、この画面を使って、対象の可能性、手元に残す証拠、今後の情報提供意向を整理してください。

参加者の実際の会員状態や通知受領状況に置き換えない。

## タスク

### T1 対象可能性の確認

「自分が対象になりそうか確認し、結果を声に出して説明してください」

観察すること:

- 迷わず開始点を見つけられるか
- 結果を「漏えい確定」「補償対象確定」と誤読しないか
- 「分からない」を選べると理解するか

### T2 証拠の整理

「今から何を保存するか決めてください」

観察すること:

- ファイルをアップロードする画面だと誤解しないか
- 原本を自分の端末に残すと理解するか
- メモ欄に会員番号などを書こうとしないか

### T3 意思表示

「更新通知と支援団体への提供について、希望を記録してください」

観察すること:

- この操作だけで通知登録が完了したと思わないか
- 弁護士への委任・訴訟参加が成立したと思わないか
- 用途別に選択できると理解するか

### T4 データ管理

「自分の記録を持ち出す方法と、消す方法を見つけてください」

観察すること:

- 書き出しと外部送信を混同しないか
- 削除範囲を正しく説明できるか

## 終了時の操作

1. 研究欄の4問に参加者自身が回答する
2. 「識別子なしの検証結果を書き出す」を押す
3. 観察者は書き出されたJSONと個人を直接特定しない観察メモだけを保存する
4. 対象確認の回答、証拠チェック、端末内メモ、意思表示の内訳がJSONに含まれないことを確認する
5. ブラウザのプライベートウィンドウを閉じる
6. 進行役は[Gate B判定キット](./gate-b-scorecard.md)の閉じた選択肢だけをmanifestへ記録する

## 成功基準

| 指標 | 第1ラウンド通過基準 | 次段階の基準 |
|---|---:|---:|
| T1〜T4を重大な支援なしで完了 | 4/5人 | 8/10人以上 |
| 対象可能性を法的確定と誤解 | 1/5人以下 | 1/10人以下 |
| ローカル記録を外部送信と誤解 | 1/5人以下 | 1/10人以下 |
| 委任・授権・訴訟参加が成立したと誤解 | 1/5人以下 | 1/10人以下 |
| 高機密情報を入力しようとする | 0人 | 0人 |
| T1〜T3を10分以内に完了 | 4/5人 | 8/10人以上 |
| 保存先を「この端末だけ」と回答 | 4/5人 | 8/10人以上 |
| 理解度（5段階）の中央値 | 4以上 | 4以上 |
| 信頼度（5段階）の中央値 | 4以上 | 4以上 |

高機密情報の入力を誘発した場合は、他の指標にかかわらず設計を修正して再テストする。

## 中止条件

- 参加者が心理的負担を示した
- 実在の通知、会員番号、本人確認書類を提示しようとした
- 個別の法的助言や補償判断を求められた
- 画面または記録方法により個人情報が残る可能性が生じた

中止時は、理由を匿名のカテゴリだけで記録し、具体的な個人情報は残さない。

## 観察メモの書式

```text
匿名ID:
実施日:
タスク完了: T1 / T2 / T3 / T4
支援回数:
重大な誤解: なし / 対象確定 / 外部送信 / 委任成立 / その他
高機密情報を入力しようとした: なし / あり（内容は記録しない）
最初に止まった箇所:
行動事実:
観察者の解釈:
次の修正候補:
```

## ラウンド判定

- 5人終了するまでは、重大な安全問題以外のUI修正を途中で入れない
- 各指標を人数と中央値で集計する
- 発言より、実際の操作と誤解を優先する
- 修正する問題は「頻度 × 被害の大きさ × 修正可能性」で順位づけする
- 第2ラウンドには第1ラウンドと同じ参加者を含めない
- Gate Bには第1・第2ラウンドの参加者を含めず、同じUIバージョンで10人を完了する
- 各段階のJSONと観察manifestは[Gate B判定キット](./gate-b-scorecard.md)で検証・集計する
