Executive summary

中央で原本を集めず、受付前の整理をつなぐ

RightsRelayは法律判断や受任を担わず、利用者による状況整理と、支援主体による独立した初期検討の間を「最小共有パケット」で接続します。

現行プロトタイプで実装済み 専門家承認後に設計・実証 現行方針では実施しない

RightsRelay

支援主体

Data boundary

何を、どこまで扱うか

同じ利用者操作でも、本人用記録・共有用パケット・集計出力は目的と含有項目が異なります。

利用者の端末内に残す

  • 対象確認の回答
  • 証拠を保有しているかのチェック
  • 500文字以内の端末内メモ
  • 更新・共有検討・調査協力の選択

最小共有パケットに含める

  • 事件ID・判定ルール版・ランダムなパケットID
  • 対象可能性、会員関係、通知受領区分
  • 証拠原本ではなく保有種類
  • 限定した意思と同意境界

共有・中央収集しない

  • 氏名、住所、連絡先、会員番号
  • 通知メール本文・画像・ヘッダー
  • 免許証・マイナンバー・カード情報
  • 証拠原本、領収書、被害明細、自由記述メモ

支援主体が書き出す集計

  • 有効パケット数と重複数
  • 対象可能性・会員関係・通知区分ごとの件数
  • 証拠種類・用途別意向の件数
  • 個々のパケットIDは出力しない

Validation loop

検証から実証へ進む判断ゲート

現在はDiscovery / Validation段階です。価値、安全性、法的境界を順番に確認し、未達なら修正・方向転換・停止します。

GATE A / 2026-11

支援主体の実務価値

弁護士・特定適格消費者団体等が、架空5件の集計を評価。初期整理時間の短縮、追加項目、法的境界、次の協力意思を確認。

GATE B / 2027-03

利用者の理解と完遂

合計20人で段階的に検証。主要タスク完了率80%以上、10分以内、重大な誤解・高機密入力の誘発がないことを確認。

GATE C / 2027-05

小規模実証の開始可否

法務・プライバシー・セキュリティ上の阻止条件を解消し、受け手となる支援主体がいる場合だけ、実データ実証を検討。

Operating boundaries

行うこと・承認後に行うこと・行わないこと

事業上もっとも重要なのは、状況整理と法律業務の境界を越えないことです。

現行で行う

  • 一次情報の出典・更新日付き表示
  • 公表条件に基づく対象可能性の整理
  • 証拠保有状況の端末内整理
  • 本人操作による最小JSON書き出し
  • 架空／本人持参ファイルの端末内集計

承認後に設計する

  • 連絡先・参加意向のサーバー受付
  • 支援主体への自動転送
  • 支援主体の認証と送信先固定
  • 同意・撤回・削除の監査証跡
  • 原本受領や真正性確認の運用

現行方針では行わない

  • 勝訴可能性・違法性・請求可否の自動判定
  • 請求・交渉・和解・通知書送付の代行
  • RightsRelay名義の受任・授権受付
  • 事件評価による弁護士ランキング
  • 紹介料・成功報酬・回復額連動課金

この図を読むときの重要な注意

「対象の可能性あり」≠「漏えいが個人について確定」≠「請求権がある」≠「委任・訴訟参加が成立」です。

  • 共有パケット数は本人確認済みの実人数を証明しません。
  • 現行プロトタイプはデータをRightsRelayサーバーへ送信せず、POST要求も受け付けません。
  • 最小共有パケットも照合可能性があるため、「匿名だから安全」とは扱いません。
