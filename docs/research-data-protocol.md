# 調査データ取扱手順

## 適用範囲

被害経験者テスト、弁護士・支援団体評価、セキュリティレビューの募集から削除までに適用する。実運用の被害者データ処理方針ではなく、企画検証段階の調査データ手順である。

## 分離する4領域

| 領域 | 含めてよいもの | 含めないもの | 保管期限 |
|---|---|---|---|
| A 連絡・日程 | 氏名または呼称、返信先、候補日時、謝礼支払状態 | 調査回答、事件名、被害内容 | セッション終了・謝礼処理・撤回対応のうち最も遅い日から30日 |
| B 同意・対応表 | 調査ID、同意日時、同意文バージョン、撤回状態、Aの連絡先への参照 | 調査回答、自由記述の観察メモ | 最終成果物の確定または2027-12-31の早い方まで |
| C 構造化評価 | 識別子なしの評価JSON、閉じた選択肢のmanifest、Gate判定JSON | 氏名、連絡先、組織名、事件名、原本、自由記述 | 2027-12-31まで。継続研究へ使う場合は再審査 |
| D 観察メモ | 調査ID、行動事実、観察者の解釈、修正候補 | 連絡先、企業名、会員番号、通知原文、被害明細 | 各Gate判定確定から90日 |

A・B・C・Dを同じファイル、同じ表、同じフォルダへ置かない。

## 調査ID

- 被害経験者: `V-001`
- 法律家: `L-001`
- 消費者団体: `O-001`
- セキュリティ専門家: `S-001`

番号は単調増加とし、氏名、イニシャル、企業名、地域、誕生日を埋め込まない。組織の重複判定が必要な場合は `ORG-001` のような別の仮コードをBだけで管理し、Cには仮コードだけを渡す。

## 保管要件

- AとBは、OSの端末暗号化が有効な管理端末または承認済みの暗号化保管場所に置く
- Cは個人を直接特定する情報を含まなくても、他情報との照合可能性を前提に保護する
- 共有リンクを「リンクを知っている全員」にしない
- 個人用メール、SNSのDM履歴、ダウンロードフォルダを恒久保管場所にしない
- バックアップ、ゴミ箱、版履歴を含めて期限後に削除できる保管方法を選ぶ
- 画面録画・音声録音は原則しない。例外は目的、閲覧者、期限、撤回範囲を別途同意した場合だけ

保管サービスが未決定の間は、A・Bを実際に収集しない。サービス選定後、アクセス制御、暗号化、削除、ログ、国外移転、委託条件を確認する。

## アクセス

- A: 日程調整担当だけ
- B: 調査責任者だけ
- C: 集計担当。Aへアクセスする必要はない
- D: セッション担当と分析担当だけ

兼務する場合も、保存場所と作業用アカウントを分け、Cの分析中にAを開かない。

## 受領時のチェック

1. ファイル名に氏名・組織名がない
2. 許可したスキーマとサイズである
3. 自由記述や未知フィールドがない
4. 実在案件データが含まれない
5. 対応する同意がBにある
6. 受領元の一時ファイルを残さない

Gate A・Gate Bの判定器が拒否したファイルを、手作業で列を削って通さない。原因を確認し、試作から再書き出しする。

## 撤回・削除

1. 参加者から連絡を受けた担当者がAから本人を特定する
2. Bで調査IDを照合する
3. Cの個別評価JSON、manifestの該当行、Dの個別メモを削除する
4. Gate判定済みなら、その参加者を除いて再計算する。必要人数を下回ったGateは未達へ戻す
5. A・Bの撤回処理記録には、受付日、完了日、担当者、削除対象カテゴリだけを残す
6. 7日以内を目標に完了し、完了連絡後30日以内にA・Bの連絡情報も削除する

バックアップや版履歴から即時削除できない場合は、復元時の再削除手順と最長残存期間を事前説明する。

## インシデント時

誤送信、紛失、アクセス権誤設定、実在データの混入を発見した場合:

1. 新規収集と共有を停止する
2. 影響ファイル、期間、アクセス者を特定する
3. 共有リンク・認証情報を失効し、可能な範囲で回収・削除する
4. 法令・契約・同意文に基づく通知要否を責任者と専門家が判断する
5. 原因と再発防止を記録し、安全確認まで募集を再開しない

「識別子なし」と表示したファイルでも、別データとの照合可能性があれば保護対象として扱う。

## 公表

- 人数が少ない属性別集計を公表しない
- 発言引用は、文言と帰属範囲について別途確認した場合だけ
- 組織名、肩書、地域、珍しい体験を組み合わせない
- Gate判定の分母、UIバージョン、除外・中止件数を併記し、都合のよい回答だけを選ばない
